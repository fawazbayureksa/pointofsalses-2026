Point of Sales 2026 API

Complete REST API reference for mobile POS apps & external integrations.

Point of Sales 2026 is a multi-tenant, cloud-based POS backend built with Laravel 11 and Laravel Sanctum. It powers the React Native cashier app and provides programmatic access to sales, inventory, shift, and reporting data for third-party integrations.


Base URL

Base URL https://<your-tenant>.yourdomain.com/api
Replace <your-tenant> with your organization's subdomain slug. All routes are tenant-scoped — you will never receive data from another tenant.

🔑 Authentication

The API uses Laravel Sanctum Bearer Tokens. Two flows are available.

Required headers (all authenticated requests)

HTTP Headers 
Authorization: Bearer <token>
Accept: application/json
Content-Type: application/json
Public endpoints — POST /auth/login, POST /auth/login-pin, and POST /auth/switch-cashier do not require the Authorization header.

Token storage (mobile)

Store tokens using expo-secure-store on React Native / Expo or EncryptedSharedPreferences on Android. On web, use httpOnly cookies. Never store tokens in localStorage.

⏱ Rate Limiting

ScopeLimitHeaders
Global per IP 60 req / min X-RateLimit-Limit, X-RateLimit-Remaining
Auth endpoints 10 req / min Retry-After

When the limit is exceeded the API returns HTTP 429. Implement exponential back-off in your client using the Retry-After header.

Rate limits can be raised for verified integrations. Contact your platform administrator.

🛡 Security Notes

  • Store tokens in expo-secure-store or Android EncryptedSharedPreferences — never in plain AsyncStorage or localStorage.
  • All traffic must go over TLS 1.2+. HTTP requests will be redirected or rejected.
  • Resources are silently scoped to the authenticated user's tenant.
  • Rotate tokens after privilege escalation (role change).
  • PINs are stored as bcrypt hashes server-side — never log or transmit PINs outside the designated login endpoints.
  • Supervisor actions (refund, void, discount override) require a short-lived action-scoped supervisor token from POST /supervisor/authorize.
  • Implement automatic logout on 401 Unauthenticated responses.

🚀 8. Integration Guide

Follow these steps to integrate the API into your mobile or frontend application.

  1. Install an HTTP client
    Terminal
    npm install axios
  2. Configure the API client
    JavaScript – src/api/client.js
    // src/api/client.js
import axios from 'axios';

const apiClient = axios.create({
  baseURL: 'https://<your-tenant>.yourdomain.com/api',
  headers: {
    'Accept': 'application/json',
    'Content-Type': 'application/json',
  },
});

// Attach stored token to every request
apiClient.interceptors.request.use(async (config) => {
  const token = await SecureStore.getItemAsync('auth_token');
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

// Handle 401 globally
apiClient.interceptors.response.use(
  (res) => res,
  async (err) => {
    if (err.response?.status === 401) {
      await SecureStore.deleteItemAsync('auth_token');
      // Navigate to login
    }
    return Promise.reject(err);
  }
);

export default apiClient;
  3. Authenticate
    JavaScript (axios)
    async function login(email, password) {
  const { data } = await apiClient.post('/auth/login', { email, password });
  await SecureStore.setItemAsync('auth_token', data.token);
  return data.user;
}

// Or with native fetch:
async function loginWithFetch(email, password) {
  const res = await fetch('https://<your-tenant>.yourdomain.com/api/auth/login', {
    method: 'POST',
    headers: { 'Accept': 'application/json', 'Content-Type': 'application/json' },
    body: JSON.stringify({ email, password }),
  });
  if (!res.ok) throw new Error('Login failed');
  return res.json();
}
  4. Make authenticated requests
    JavaScript
    // Fetch paginated products
const { data } = await apiClient.get('/products', {
  params: { page: 1, per_page: 20, outlet_id: 1 }
});

// Create an order
const { data: order } = await apiClient.post('/orders', {
  outlet_id: 1,
  items: [{ product_id: 5, quantity: 2 }],
});

// Process payment
await apiClient.post(`/orders/${order.id}/pay`, {
  payment_method: 'qris',
  amount: order.total_amount,
});
  5. Handle errors consistently
    JavaScript – error helper
    async function safeRequest(fn) {
  try {
    return await fn();
  } catch (error) {
    const status  = error.response?.status;
    const message = error.response?.data?.message ?? 'Unexpected error.';
    const errors  = error.response?.data?.errors ?? {};

    if (status === 422) {
      throw new Error(Object.values(errors).flat().join('\n'));
    }
    throw new Error(message);
  }
}
Scalability tip: Cache product and category lists locally with a 10-minute TTL. Use exponential back-off on 429 Too Many Requests responses. For offline support, queue failed order mutations and replay them on reconnect.
